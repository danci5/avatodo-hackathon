# Optional Google Drive copies

In Avatodo Settings, choose Google Drive and sign in to your own Google account. Google presents the requested access before connecting. TestFlight users do not need a Google Cloud project or Google API key.

Avatodo creates a visible **Avatodo** folder and uploads one readable file for each saved note, task or checklist. **Settings → Google Drive → File format** offers Markdown (the initial choice) or Plain text. Plain text is the compatibility option for viewing inside mobile Drive clients; it preserves the title/body and readable checklist marks without the Markdown export envelope. File names use the note title without a visible internal ID or extension. The actual text/Markdown type stays in Drive metadata; identical or reserved titles get a simple number. Drive displays its modified date/time separately. Existing current-note copies are renamed in place on upload. Switching formats updates the same Drive file ID, including when the note revision is unchanged; it does not create a second copy. Later local edits update the same file, including its title and checked items. Uploads run directly from iPhone to Google while the app can run and reach the network. They do not delay the companion's reply. Notes remain usable locally when disconnected or offline.

This is outbound copying, not two-way synchronization. Drive edits are not imported. Deleting a local note or disconnecting does not delete an existing Drive copy; manage those copies in Google Drive. Disconnect signs out on this iPhone and stops uploads. You can separately revoke the app's access in your Google account. Use Upload now after resolving an error; an incomplete upload is not reported as up to date.

The app requests `drive.file` and basic sign-in information. It can access app-created or explicitly selected files, not the whole Drive. Google credentials stay in the iPhone's Google Sign-In Keychain storage. They never go to Meta, Watch or an Avatodo backend. Conversation history, edit receipts and the Meta key are not uploaded. Notes and their stable identifiers/revisions are included in the exported file or its app-owned Drive metadata.

Connecting Muse or another assistant is a separate authorization. The assistant must support reading these actual Markdown files. The Muse reading/demo step is not established by the exporter tests.

## Self-building and forks

The supplied iOS OAuth client identifies the maintainer's `app.avatodo` app and signing team. It is a public native-client identifier, not a secret. If you change the bundle identifier or signing team, create your own iOS OAuth client in Google Cloud, enable the Drive API and configure its consent screen for the narrow scopes above. Set `GIDClientID` and the matching reversed-client-ID URL scheme in `project.yml`, then regenerate the Xcode project. A native client does not require a client secret or hosted backend. Check Google's publication requirements for your own app.

The official Google Sign-In SDK is pinned in the Xcode package resolution. Google manages the sign-in UI, credential storage and refresh. The exporter reserves remote IDs before creates, scopes its local index to the connected account, rejects duplicate/ambiguous targets and validates provider responses without displaying credentials or response bodies.

## Verification boundary

Twelve automated export tests cover Markdown content, folder/files without sharing permissions, stable retry IDs, revision skipping, account separation, corrupt/duplicate targets and safe failures. Native iPhone/Watch builds and the real Google sign-in entry/cancel flow have passed in Simulator. Google Cloud shows the app In production and says its requested data scopes do not require sensitive/restricted-scope verification. The owner subsequently confirmed a real personal-account upload. The exact uploaded Markdown note rendered correctly in Drive’s web viewer, while the owner’s iPhone Drive app reported Unsupported file type. No user-note content was placed in source or fixtures. The owner also confirmed that a plain-text copy opens inside iPhone Drive after manually removing .txt. This is physical viewer evidence on the prior build, not acceptance of the new automatic naming migration. Automatic clean-title migration, repeated remote updates and Muse read-back remain to verify; no simulator account permission was granted during the sign-in entry check.

Markdown can be previewed on Drive’s web viewer and opened in Docs without converting the file. Some mobile Drive clients cannot render it. The plain-text setting provides a text/plain alternative inside Drive; Avatodo does not install a Drive extension, add an Open-in-Avatodo reader, or convert files to Google Docs. See [Google’s previewable file types](https://support.google.com/drive/answer/37603) and [Markdown guide](https://support.google.com/docs/answer/18289341).
